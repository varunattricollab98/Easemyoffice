# Multi-state quotation selection, per-row removal, email logo grid, and sticky sidebar (v1)

Four independent changes bundled under one task on the Send Quotation flow. The state picker in the send dialog becomes a multi-select (Popover + Command + Checkbox) so a rep can combine plans from several states into one quotation, while a derived single-state path preserves the old state+city behavior. Each pricing row gains a frontend-only remove button so the rep can drop cities the client didn't ask for without touching the sheet. The email's brand-logo block was rebuilt as an email-safe fixed table and pruned of broken/duplicate/hotlinked logos. The left app sidebar was made sticky at `lg+`. Price overrides and removals are re-keyed from list index to a stable `planKey` so edits stay glued to the right plan across multi-state combines and after removals.

Watch for: price overrides and removed rows are reset on state toggle and dialog open, but **not** on service-type change (possible) — dormant-then-reactivating overrides if a rep flips service type and back. Everything else traced clean: the outgoing email is built from the same post-removal `displayPlans` the editor shows (confirmed), no backend/sheet mutation was added for removal (confirmed), and the sticky sidebar has no overflow ancestor defeating it (confirmed).

**Verdict**: APPROVED

## High-level view

The multi-select is assembled entirely from existing UI primitives rather than a new dependency, and it degrades to the classic flow via `isSingleState`/`selectedState` derivations — the city sub-select, location label, and subject line all branch off the same single-vs-multi distinction, so the single-state regression surface is small. When two or more states are selected the city filter is deliberately disabled and `selectedCity` cleared, with an inline note explaining why.

The stable-key rework is the load-bearing change. `planKey` embeds the plan's identity plus its index within `filteredPlans` (the list that does *not* shrink on removal), so removing one row never renumbers the others. Both `priceOverrides` and `removedRowKeys` are keyed this way, and the same keyed set feeds the editor table, the "+N more" truncation, the preview, and the email — so what the rep sees is what the client gets.

Row removal is frontend-only: `handleSend` posts the rendered `emailHtml` and never calls a delete against the sheet or Supabase, matching the explicit requirement that the backend not be touched.

The logo grid is now an inline-styled `role=presentation` fixed table with eight self-hosted logos at uniform height, replacing a block that carried a duplicate HomeLane, three risky hotlinked URLs, and mismatched alt text.

The sidebar change is a one-class edit (`sticky top-0 h-screen`) on an `<aside>` whose nav already scrolls internally, under a `min-h-screen flex` parent with no overflow clipping — the correct setup for sticky.

### Multi-select built from existing primitives, single-state path preserved

The state `Select` is replaced by a `Popover` + `Command` + `Checkbox` combobox with a `Button` trigger, all already in the codebase — no new dependency. `selectedStates: string[]` is the new source of truth; `isSingleState` and the derived `selectedState` reconstruct the old scalar so the city derivation, `locationLabel`, and subject line keep working when exactly one state is chosen. `filteredPlans` matches `p.state` case-insensitively against a `Set` of the selected states, collapsing to the old single-state filter for one selection.

The two-plus-state case is gated consistently: the city sub-select renders only on `isSingleState`, `toggleState` clears `selectedCity`, and the city filter in `filteredPlans` is guarded by `isSingleState && selectedCity`, with an inline note that city filtering is off. `locationLabel` joins up to three state names then falls back to "N States"; the subject line reuses it. The single-state flow is the `length === 1` branch of the same derivations rather than a separate code path, which keeps the regression surface small.

### Stable planKey keeps overrides and removals aligned

```
planKey(p, idx) = code|state|city|area|idx   // idx from the non-shrinking filteredPlans
keyedFilteredPlans = filteredPlans.map((p,i) => ({ key: planKey(p,i), plan: p }))
displayPlans       = keyedFilteredPlans.filter(k => !removedRowKeys.has(k))
```

The load-bearing property: `idx` is the position in `filteredPlans`, derived purely from `allPlans`/`serviceType`/`selectedStates`, and does not contract when a row is removed. Removal only subtracts keys in `displayPlans`, so surviving rows keep their keys and their overrides. The trailing index disambiguates genuine duplicate sheet rows sharing code/state/city/area, which a pure-identity key would collide. Both `priceOverrides` (migrated from `Record<number,number>` to `Record<string,number>`) and `removedRowKeys` use these keys, and the editor `<tr key={key}>`, the input `onChange`, the preview, and `emailHtml` all read the same keyed structure.

One asymmetry (possible): `toggleState` and the open-effect reset both `priceOverrides` and `removedRowKeys`, but the service-type `onValueChange` resets neither. With identity keys this no longer mis-applies an override to the wrong plan (as index keys could have) — a stale GST-plan key won't be found among the new service's keys, so it lies dormant. The catch is reactivation: switch service type away and back with the same states, and the dormant overrides/removals reappear. Low severity; the cheap fix is to clear both in the service-type handler for parity with `toggleState`.

### Email matches the editor exactly

`emailHtml` maps over `displayPlans` (post-removal, multi-state), applies overrides by key, and passes the result to `buildQuotationHtml`, which renders every plan it receives — it does not slice. The editor table slices to the first 10 for display and shows "+ N more … included in the email"; both the "10" and the "N more" count `displayPlans`, not the raw filtered list, so the truncation note stays truthful and removals/edits visible in the editor are exactly what the email carries. Preview and Send are disabled on `displayPlans.length === 0 || selectedStates.length === 0`, and the empty-state copy distinguishes "all rows removed" from "no plans for this selection".

### Row removal is frontend-only

`removeRow` adds a key to `removedRowKeys`; `restoreAllRows` empties the set. `handleSend` invokes `send-client-email` with `{ to, subject, html: emailHtml, … }` — nothing references the removed rows or writes back to the sheet. No delete or mutation against Supabase or the plans sheet was introduced, satisfying the explicit "backend must not be touched" constraint.

### Email-safe logo grid

The `<!-- BRAND LOGOS -->` block is now a `role="presentation"` table with `table-layout:fixed`, two rows of four `width="25%"` cells, inline styles only, and all eight logos normalized to `height:22px`. The prior block carried a duplicate HomeLane (one hotlinked from framerusercontent, one self-hosted), plus hotlinked rosierfoods and Supabase-hosted "Sleepy Cat" images; those three risky external URLs were dropped and the duplicate resolved to the single `easemyoffice.in`-hosted HomeLane. Alt text that previously read "uptodd" for fitelo and had EarthtronEV/KineticGreen swapped is corrected. The block sits outside the per-serviceType branching so all five service types get it. Sandbox network mode blocks fetching the URLs to verify they resolve (possible), but all eight now point at the same `www.easemyoffice.in/logos/` origin the rest of the template already uses.

### Sticky sidebar

`app-shell.tsx` adds `sticky top-0 h-screen` to the existing `hidden lg:flex … <aside>`. The `sticky`/`top-0` utilities aren't `lg:`-prefixed, but the element is `hidden` below `lg`, so there's no effect at smaller widths and `MobileTabBar` is untouched. The `<aside>`'s nav is `flex-1 overflow-y-auto`, so with `h-screen` the sidebar is self-contained: header and footer pinned, nav scrolls internally, and long nav lists won't push the sticky element taller than the viewport. The parent in `_authenticated.tsx` is `min-h-screen flex bg-background` with no `overflow-hidden`/`overflow-auto` ancestor between it and the aside to defeat the sticky positioning.
