# Documentation analytics dashboard with escalation system (v2)

All five issues from the v1 review have been addressed: RLS policies now use `DROP POLICY IF EXISTS`, escalation threshold is fetched through a single shared `useEscalationThreshold()` hook, `useMemo` was replaced with `useEffect` for state sync, and code comments document both the `updated_at` proxy assumption and the intentional split-brain escalation design.

Watch for: period-filtered queries hide the oldest stuck tasks from escalation detection (confirmed), meaning the tasks most in need of escalation are the least visible in the dashboard.

**Verdict**: APPROVED

## High-level view

The period filter (`created_at >= filterISO`) applies to both the Analytics and Tasks tabs, which means escalation detection only operates on the visible subset. A task created 3 months ago that hasn't been touched in 15 days won't appear in the "monthly" analytics view and won't show up in the escalated tasks section. This is worth a follow-up fix (either a separate unfiltered query for escalated tasks, or excluding the period filter from escalation logic) but is not blocking given that admins can switch to "yearly" as a workaround.

## Period filter blinds escalation detection to old tasks

Both `AnalyticsTab` and `TasksTab` apply `.gte("created_at", filterISO)` before computing which tasks are auto-escalated:

```typescript
// AnalyticsTab
.gte("created_at", filterISO)  // only tasks created in this period

// Then later:
const escalatedTasks = useMemo(() => {
  return tasks.filter((t) => {
    if (t.escalated) return true;
    if (t.stage !== "completed") {
      const daysSinceUpdate = differenceInDays(now, new Date(t.updated_at));
      return daysSinceUpdate > escalationDays;
    }
    return false;
  });
}, [tasks, escalationDays]);
```

The `tasks` array only contains tasks from the current period. If an admin is viewing "daily" or "weekly", any task older than that window is excluded entirely — including tasks that are 30 days stuck and desperately need attention. The escalation system's value proposition is surfacing forgotten work, but the period filter actively hides the most forgotten work.

The TasksTab has the same constraint: its escalation row-highlighting and badge only apply to tasks present in the filtered result set. An admin switching from "monthly" to "yearly" will suddenly see a burst of escalated tasks that were invisible moments before.

A clean fix would be a separate query in `AnalyticsTab` that fetches all non-completed tasks regardless of `created_at`, used solely for the escalated-tasks section and bottleneck count. The period filter would continue to govern the completion metrics and per-person table (where it makes sense).

**Confidence: confirmed** — the `.gte("created_at", filterISO)` is applied before the escalation memo in both tabs.
